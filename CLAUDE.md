# AwakeTab — agent guide
Purpose: a browser tab that keeps the screen awake, honestly. Monorepo: apps/site (Next.js 16 + Tailwind 4 + shadcn/ui, deployed as the Cloudflare Worker `awaketab-site` through OpenNext), apps/extension (WXT MV3), packages/wake (@awaketab/wake), packages/core (@awaketab/core), scripts/ (licence keys, KV backups, lint helpers), docs/.
Start here: docs/00-conventions.md (identifiers, budgets, gates) → docs/02-prd.md (requirements) → the spec for the area you touch.
Design: PRODUCT.md → DESIGN.md (Glance design system) → docs/plan/glance/AGENT_PROMPT.md (full spec) → docs/redesign/DECISIONS.md → skill `.claude/skills/awaketab-design` (Cursor: `.cursor/rules/awaketab-design.mdc`).
Commands: pnpm install · pnpm dev (the Next site on :3000) · pnpm format · pnpm lint (includes pnpm knip: unused files, exports, dependencies) · pnpm typecheck (the four workspaces, then the root scripts) · pnpm test (unit + site) · pnpm build · pnpm -F site preview / deploy (OpenNext on Cloudflare) · pnpm -F extension dev.
Contracts you may not change without a docs update: the seven lock states and pill copy (docs/04, docs/05), storage keys (docs/08), routes and slugs (docs/00 §7), ad placement rules (docs/00 §8.3, docs/09), performance budgets (docs/00 §11), the design tokens (the shadcn variables in `apps/site/app/globals.css` and the extension's `--at-*` tokens in `apps/extension/src/styles/tokens.css`; DESIGN.md).
Definition of done: acceptance criteria met, tests green, docs updated (00-conventions.md first for identifiers), changelog fragment when user-visible.
Formatting: Prettier (`.prettierrc.json`, 120 columns). Run `pnpm format` before committing; `pnpm lint` checks it.
Code comments: only a short `//` line where the reason is not obvious; no block, JSDoc, HTML or CSS comments (tool directives excepted). `pnpm lint` runs `scripts/comments.mjs`; `--fix` strips them.
Commits and PRs: plain English, no internal codes, no AI attribution; author is the owner.
Testing cadence: every change runs lint, typecheck, unit tests, build and size. The extension has its own Playwright suite (`pnpm test:e2e:ext`); the Next site has no browser e2e suite yet, so check UI changes on the preview against the design. GitHub runs CI on every push to `main` and `play` and on every pull request; hosting and deploys are in docs/DEPLOYMENT.md.
Branches: cut a feature branch from the latest `main`, merge it into `play` first (deploys to play.awaketab.com, internal testing only), test there, then merge the same feature branch into `main` (deploys to awaketab.com). Never merge `play` into `main`.
